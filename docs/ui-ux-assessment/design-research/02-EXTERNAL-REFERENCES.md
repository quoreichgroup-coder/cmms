# External design research and reference evidence

**Research date:** 2026-10-10. **Purpose:** extract reusable interaction patterns, never copy a complete screen, visual identity, or artwork. Directly inspected pages are separated from search-index results and inaccessible sources.

This exceeds five inspectable references across Dribbble, Carbon, Fiix, Microsoft Learn, and a live product page. The Dribbble inspection used the current shot previews and their project-page descriptions; the dated QPM current-state images used for comparison remain in `docs/validation-pilote/2026-10-03/`. The strongest workflow evidence is R5/R6; R1–R4/R11 are visual/concept inspiration only.

## Access gaps and next research pass

- **Behance:** search surfaced [Maintenance Management Dashboard](https://www.behance.net/gallery/239472741/MAINTENANCE-MANAGEMENT-DASHBOARD-WEB-APP-UI-DESIGN) and other maintenance projects, but direct project fetch returned 403. Search metadata is not enough to claim screen-level inspection; exclude it from the reviewed-reference count.
- **Mobbin:** no relevant specific maintenance/field-service flow could be verified in this browser session. Use a signed-in human review if licensed access is available; record product, screen sequence and access date.
- **Figma Community:** direct community search was blocked by robots; official Figma help confirms community resources exist, but no specific UI kit was inspected. Do not treat a generic kit as design evidence.
- **Material Design:** official adaptive-layout result was indexed; its page body could not be extracted. Re-open manually in browser/design team and inspect exact layout patterns before prototyping.

The next research board should add screenshots only where rights/access permit, date/source attribution, intended role/device, extracted pattern and an explicit “adapt / reject” rationale. No QPM screenshot or external visual was copied into a new asset.
