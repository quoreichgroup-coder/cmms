# Design direction comparison by UX family

This is a decision proposal, not a final visual mockup. “Current QPM” describes source architecture and historic supplied evidence; it is not a complete live visual inspection. Three approaches are compared per family. The recommendations preserve API payloads, existing business rules and role/feature gates.

## Common choice criteria

1. Keep the next operational action and required context visible together.
2. Prefer table density for comparison-heavy desktop queues and cards for narrow/field contexts.
3. Reserve tabs for views of the same record; Carbon recommends no third navigation depth and short tab labels. The existing historical asset screenshot reinforces the need to test overflow on native.
4. Make status readable as text plus shape/icon/color; priority is a separate urgency dimension.
5. Preserve current validations, state transitions, permission checks, endpoint shapes and entitlement visibility.
6. Distinguish visual proposals from additions such as saved views, bulk actions, offline queue, dispatch calendar or new workflow statuses; those require separate approval/API analysis.
