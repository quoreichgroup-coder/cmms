# Proposition de tokens QPM Mobile

Statut : première tranche d’implémentation présente dans le dépôt. Les tokens proposés ci-dessous sont centralisés dans `mobile/theme/tokens.ts` et alimentent `mobile/custom-theme.ts`; les valeurs Auth restent la référence de marque. Contraste automatisé vérifié pour les couleurs textuelles et états sémantiques sur la surface de base. Le rendu sur appareils, les surfaces secondaires et les écrans utilisant encore des couleurs littérales restent à contrôler.

## Typographie, espace, rayon et élévation

| Famille       | Échelle proposée                                                                                                                                                                                                  |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Typographie   | Material 3 système natif; `display 28/34 700`, `title 20/26 700`, `section 16/22 700`, `body 14/20 400`, `label 12/16 600`, `caption 12/16 500`. Ne pas descendre sous 12 px pour un contenu utilisateur courant. |
| Espacement    | base 4 px; `1=4`, `2=8`, `3=12`, `4=16`, `6=24`, `8=32`, `10=40`. `qpmLayoutTokens.space` est implémenté et utilisé dans cartes annuaire, listes d’actifs/WO liés, état asynchrone et pagination.                 |
| Rayon         | `control=10`, `card=16`, `cardLarge=20`, `sheet=24`, `pill=999`, centralisé dans `qpmLayoutTokens.radius`; les cartes de contenu des listes et écrans opérationnels utilisent `cardLarge`, les surfaces denses internes gardent `card`. |
| Cible tactile | 48 dp au minimum; icône visuelle plus petite peut conserver hitSlop si plateforme le permet.                                                                                                                      |
| Élévation     | niveau 0 bordure seulement; niveau 1 carte douce; niveau 2 menu/dialogue. Ombres discrètes en clair, bordure + différence de surface en sombre.                                                                   |

## Composants et frontières

Prolonger React Native Paper et le thème Material 3 existants : champs (normal/focus/erreur/désactivé), boutons (primaire/secondaire/texte/danger), barres de navigation, cartes de WO, badges avec foreground/background de statut, dialogues, bottom sheets/action sheets, snackbars, placeholders/erreurs et graphique. Garder les états métier dans les helpers existants; ces tokens ne modifient ni transitions ni permissions.

Les illustrations d’auth utilisent `brand.primary`, une ligne de contour blanche translucide et `surface.base` pour la vague en clair. La vague sombre utilise `surface.canvas`; la forme conserve sa composition. Les graphiques doivent associer couleur et légende/valeur/forme afin d’éviter une lecture dépendant uniquement de la teinte.
