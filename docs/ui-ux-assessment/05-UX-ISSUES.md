## Confirmed issue count

Using the confidence and severity above: **1 confirmed critical operational issue from supplied logs, 3 confirmed medium issues, and 1 confirmed low-severity issue**. The medium issues include one dated historical screenshot, one source-level submission race and one cross-platform approval workflow mismatch. UXR-16 is a source-level localization/contrast defect. These now have source mitigations; current-device behavior still needs verification. Two documented runtime defects await current-instance revalidation (analytics opaque error and previous PM field feedback); remaining listed items are usability hypotheses or architecture facts with unmeasured impact. Do not add hypotheses to confirmed defect totals.

## Top 10 improvement opportunities

1. Stabilize API start/schema compatibility and make failure recovery visible (UXR-01).
2. Revalidate and standardize analytics loading/error/empty/retry behavior (UXR-02).
3. Reorganize navigation around role tasks while protecting existing permission/feature filters (UXR-03).
4. Close the request → asset-state decision → WO creation parity gap, then optimize Home → assigned WO → execution → completion (UXR-04, UXR-06, UXR-15).
5. Progressive disclosure for PM standard vs strategy/multi-counter setup (UXR-05).
6. Turn equipment detail into a clear 360 entry point across history/WO/meters/files/parts (routes in app.tsx, `Assets/Show`).
7. Adopt consistent data-table recipes and intentional mobile list/card behavior (UXR-07).
8. Standardize field-level validation and protect composite inputs during submission; verify recovery (UXR-09, UXR-14).
9. Test responsive/accessibility coverage, including PM status contrast and localized cycle logic (UXR-08, UXR-16).
10. Clarify company/site/licensing/document snapshot states and audit actions (UXR-10, UXR-11).
