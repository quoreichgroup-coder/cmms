# Work Order PDF review evidence

`qpm-work-order-sample.pdf` was generated by the real PDFME 6.2.8 renderer test. It includes an embedded sample company logo, company name, legal name, registered address, registration and tax IDs, Work Order and asset/location identity, 45 operation rows, labor, materials, safety/closeout notes, and signature areas. The test parsed the resulting PDF and confirmed that long operations data caused continuation beyond the four configured Job Card pages.

The following PDFs were generated from `ConfigurableWorkOrderReportRendererTest` on 24 October 2026. They are the native QPM report renderer outputs:

- `job-card-landscape.pdf`: A4 landscape, one page, branding, identity, operations, sign-off and page numbering.
- `job-card-sparse-portrait.pdf`: A4 portrait, one page, sparse optional fields omitted.
- `job-card-long-portrait.pdf`: A4 portrait, five pages from 100 operation rows; tests confirm repeated table headings, page numbers, and retention of the final row.

All values are synthetic test data (`WO-24810`, `WO-0042`, `P-204`, and sample personnel). The artifacts demonstrate renderer output and pagination only. They are not based on customer or production Work Orders and have not yet passed visual human inspection.

Visual inspection was attempted in the current environment. The installed Chromium Snap refuses to start because its AppArmor confinement service is unavailable, and no PDF rasterizer is installed. The generated PDFs are ready for review in a desktop PDF viewer before publishing the pilot template.
