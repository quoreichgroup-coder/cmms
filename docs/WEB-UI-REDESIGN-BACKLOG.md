## Reprise et validation de production — 18 octobre 2026

- Le commit `b29057f0` de `projet` est le code source déployé sur le VPS. Les images locales Docker `atlas-cmms-backend:local` et `atlas-cmms-frontend:local` ont été reconstruites depuis ce checkout et les conteneurs API/frontend recréés avec `docker-compose.license.yml`. PostgreSQL et ses volumes n’ont pas été redémarrés ni modifiés.
- Après démarrage, `/api/health-check` répond HTTP 200, la page Web répond HTTP 200, et `/api/license/state` confirme `valid=true`, `readOnly=false`, plan ENTERPRISE. Liquibase annonce la base à jour; aucun échec de démarrage Hibernate n’apparaît dans les journaux contrôlés.
- Contrôle HTTP non authentifié du nouvel échange OAuth : sans `Origin`, réponse 403; avec l’origine QPM configurée et sans session de grant, réponse 401. Ces refus vérifient les barrières négatives; le SSO positif Google/Microsoft, les cookies de session derrière TLS/proxy et l’échange jusqu’à la connexion restent à tester avec un compte de recette.
- Après déploiement : suite de tests frontend `node --test --test-reporter=dot scripts/*.test.cjs`, TypeScript `npx tsc --noEmit --pretty false`, ESLint ciblé sur les fichiers OAuth/sélecteur Request et `git diff --check` réussissent. Le build Docker Web/API optimisé a également réussi.
- Reprise SEC-WEB-03 : l’état d’authentification React est désormais vidé même si le navigateur refuse l’accès au stockage local pendant le logout; une erreur de nettoyage ne masque plus une erreur serveur initiale. Des tests couvrent les deux erreurs simultanées et la panne de stockage seule; les essais navigateur sans réseau et avec stockage bloqué restent à faire.
- La recette visuelle Chromium n’a pas pu être exécutée dans cet environnement : le Chrome DevTools configuré ne trouve pas Chrome et le binaire Snap installé refuse de démarrer faute de service AppArmor. UX-01, les captures responsive et le contrôle visuel/authentifié par rôle restent ouverts. Le contrôle direct sur le VPS prouve la santé des services, pas la réussite du workflow GitHub Actions ni la publication d’images sur Docker Hub.

### Complément de périmètre demandé — identification des équipements depuis le Web — 16 octobre 2026

L’actif possède déjà `barCode` et `nfcId` dans le backend; l’API de consultation NFC/code-barres applique l’entitlement `NFC_BARCODE`, la société et l’accès à l’actif. La fiche Web affiche un QR dérivé du code-barres, permet de télécharger le QR et imprime maintenant une étiquette paysage avec le nom, le code et le QR; les formulaires Web exposent l’identifiant NFC quand l’entitlement le permet.

**Parcours recommandé :**

1. Un administrateur prépare depuis le Web une étiquette d’actif imprimable contenant son code lisible et un QR qui reprend le `barCode` existant. L’étiquette ne contient pas d’information sensible; elle sert d’identifiant, pas de preuve d’autorisation.
2. L’étiquette est apposée sur l’équipement. L’application mobile lit le QR et ouvre l’actif correspondant via l’API authentifiée. Une saisie manuelle reste disponible si la caméra ou le code échoue.
3. Pour le NFC, on pose un tag physique compatible. Le technicien/enrôleur ouvre l’actif dans l’application mobile, lit le tag et enregistre son identifiant dans `nfcId`. Il n’y a pas de « génération » logicielle d’un UID NFC : il provient du tag. La saisie Web de `nfcId` reste un recours administratif pour corriger ou préparer une association, avec les contrôles d’unicité et d’accès du serveur.
4. Le Web pourra ultérieurement proposer un scan caméra QR/code-barres, avec HTTPS, demande de permission explicite et saisie de secours. Ce besoin est séparé de l’impression et doit être testé sur les navigateurs réellement supportés.

Le scan NFC navigateur est hors du parcours de référence : l’implémentation mobile actuelle lit un identifiant de tag (`tag.id`), tandis que Web NFC est une API expérimentale, à disponibilité limitée, centrée sur les messages NDEF et qui n’expose pas les opérations bas niveau. La lecture mobile reste nécessaire pour le flux NFC actuel. Aucune bibliothèque ou API backend n’est ajoutée dans ce lot.
